# multirotor-sim

A multirotor flight simulator with a cascaded PID controller and an
automatic PID tuner.

> **Status:** Milestone 5 (disturbances) is complete. The core is pure,
> deterministic TypeScript. `npm test` runs the fast suite and `npm run
> test:slow` runs the seeded 120 s statistics; run them for the current counts.
> No autotuner yet; see the roadmap.

## Goals

- Simulate rigid-body multirotor dynamics (6-DOF, motor lag, drag, wind).
- Fly it with a cascaded controller (position → velocity → attitude → rate).
- Automatically find good PID gains by optimising a step-response cost.
- Visualise flights in a 3D browser viewer.

## Roadmap

- [x] **M1 — Rigid-body physics:** 6-DOF state, Newton–Euler dynamics with the
      gyroscopic term, RK4/Euler integrators, conservation test suite
- [x] **M2 — Multirotor model:** motor thrust/torque from RPM², quad/hex/octo
      layouts, mixer matrix, motor lag, drag, ground contact
- [x] **M3 — Cascaded PID controller:** rate → angle → position loops,
      filtered derivative, anti-windup, waypoints
- [x] **M4 — 3D viewer:** Three.js scene, trail, live plots, gain sliders
- [x] **M5 — Disturbances:** wind gusts, sensor noise, battery sag, payload shift
- [ ] **M6–7 — Autotuner:** step-response scoring, CMA-ES / Bayesian
      optimisation, Ziegler–Nichols baseline, before/after comparison
- [ ] **Polish:** README GIF, "tune your own drone" config

## Install (development)

Requires Node 20.19 or newer (Vite 8).

```bash
git clone https://github.com/axnast/multirotor-sim.git
cd multirotor-sim
npm install
```

## How to run tests

```bash
npm test            # fast Vitest suite (single run)
npm run test:slow   # seeded 120 s statistics (3 files)
npm run test:watch  # watch mode during development
npm run typecheck   # strict TypeScript check
npm run demo        # 10 s tumbling-box CSV trace -> out/drop-box.csv
npm run demo:hover  # 3 x 10 s hover, takeoff and roll-pulse trace -> out/hover.csv
npm run demo:flight # hex takeoff, square waypoints and hold -> out/flight.csv
npm run demo:disturbance # 3 controllers x 7 rows x 5 seeds -> out/disturbance.csv
npm run dev        # browser viewer at http://localhost:5173/
npm run build      # static viewer site in dist/
npm run preview    # serve the built site locally
```

`npm run demo:hover` writes a 1 kHz, 41-column CSV (30 003 rows) with
commanded and achieved wrenches, ground impulses and energies; the model and
sign conventions are documented in [docs/multirotor.md](docs/multirotor.md).
`npm run demo:flight` writes a 1 kHz, 35-column CSV of setpoint and actual
flight states under the cascaded controller; see [docs/control.md](docs/control.md).
`npm run demo:disturbance` writes the five-seed baseline table below (seven
rows × three controller variants × two windows); see
[docs/disturbances.md](docs/disturbances.md). It takes about 13 minutes.

CI runs `npm ci`, `npm run typecheck`, and the fast `npm test` on Node 20, 22,
and 24, plus `npm run build` on Node 22. `npm run test:slow` runs in a separate
Node 22 job (25-minute timeout) on pushes to `main` and manual dispatch only;
the fast matrix remains the main signal. A separate workflow builds with Vite's
configurable `VITE_BASE` and publishes the viewer to GitHub Pages on every push
to `main`.

[Live demo](https://axnast.github.io/multirotor-sim/) · [viewer notes](docs/viewer.md)

The viewer runs the same core simulator and cascaded controller at a fixed
1 kHz. It shows the hex airframe built from its config, spin-direction-coloured
rotors, body axes with a permanent +x nose marker, a trail, an amber setpoint
marker, orbit/follow camera, live plots and a HUD.

```bash
npm run dev      # http://localhost:5173/
npm run build    # dist/ (set VITE_BASE for GitHub Pages)
npm run preview  # serve dist/ locally
```

Use the mission buttons (Hover, 5 m step, Square, Takeoff), click the ground to
set a waypoint, adjust the altitude/yaw sliders, change gain sliders live, or
pick a speed from 0.25× to 4×. `Space` pauses, `S` steps one millisecond,
`R` resets the flight, `F` toggles follow camera and `A` toggles the body axes.
Gain changes are bumpless: stored integrals are rescaled so `ki·integral` is
preserved. See [docs/viewer.md](docs/viewer.md) for the runner, coordinate
mapping and deployment details.

## Baseline results

True-position RMS (m): mean [min, max] over **five development seeds 1–5**,
120 s runs, sensors off. Windows are **20–60 s** (transient) and **90–120 s**
(steady). Generated by `npm run demo:disturbance` into `out/disturbance.csv`.

| Row | Window | M3 gate | default | gate off |
|---|---|---|---|---|
| calm | 20–60 s | 0.000 | 0.000 | 0.000 |
| calm | 90–120 s | 0.000 | 0.000 | 0.000 |
| light | 20–60 s | 0.919 [0.786, 0.996] | 0.863 [0.651, 0.996] | 0.609 [0.444, 0.762] |
| light | 90–120 s | 0.418 [0.313, 0.553] | 0.369 [0.299, 0.493] | 0.346 [0.251, 0.399] |
| moderate | 20–60 s | 2.956 [2.295, 3.421] | 2.957 [2.298, 3.421] | 2.122 [1.410, 2.811] |
| moderate | 90–120 s | 1.531 [1.098, 2.160] | 1.529 [1.096, 2.162] | 1.352 [0.949, 1.580] |
| gusty | 20–60 s | 4.043 [2.484, 5.427] | 4.044 [2.486, 5.427] | 3.592 [2.239, 5.272] |
| gusty | 90–120 s | 2.859 [1.917, 4.052] | 2.859 [1.916, 4.055] | 2.763 [1.853, 3.234] |
| strong | 20–60 s | 5.895 [4.310, 7.072] | 5.896 [4.316, 7.072] | 4.347 [2.713, 5.993] |
| strong | 90–120 s | 3.201 [2.147, 4.840] | 3.199 [2.147, 4.840] | 2.857 [1.945, 3.453] |
| constant 5 m/s | 20–60 s | 3.683 (det.) | 0.769 (det.) | 1.445 (det.) |
| constant 5 m/s | 90–120 s | 3.680 (det.) | **0.0059** (det.) | 0.0365 (det.) |
| +20 % mass | 20–60 s | 4.990 (det.) | 0.966 (det.) | 2.733 (det.) |
| +20 % mass | 90–120 s | 4.990 (det.) | **0.0077** (det.) | 0.0787 (det.) |

**M3 gate** = `integralDwell = 0` (pre-fix gate, bit-identical to M3);
**default** = the persistent-error release is active; **gate off** =
`integralSeparation = 1e9`, a plain-integration reference that overshoots a 5 m
step by 12.7 % and is not a viable controller. The constant-wind and +20 %
mass rows have no stochastic component with sensors off, so all five seeds are
identical: their zero spread is by construction, not a confidence interval.

Gust scenarios are a **known weakness and the autotuner's target**. The release
fixes the constant-wind and payload equilibria but is neutral under gusts
(gate and default differ by <0.002 m). Gate off lowers the 20–60 s gust RMS by
11–29 % across all five paired seeds, but is worse on constant wind (1.445 vs
0.769 m at 20–60 s, 0.0365 vs 0.0059 m at 90–120 s); M6 must beat **both**
references. Gusty < strong in 90–120 s is reported but not asserted: one of the
five paired differences is negative. Seeds 1–5 are development seeds; M6 will
pre-register the mean RMS over [20, 120] s per scenario on held-out seeds
1001–1020, compared by paired differences against all three references. See
[docs/disturbances.md](docs/disturbances.md) for the statistics and caveats.

## Project layout

```
src/core/math/        pure Vec3, Quat, Mat3 primitives
src/core/             rigid-body dynamics, integrators, energy diagnostics
src/core/multirotor/  config, motors, mixer, dynamics, ground contact
src/core/control/     PID, attitude, position loops and the cascade
src/viewer/           Three.js viewer, runner, plots and controls
tests/                Vitest unit and physics tests
scripts/              runnable demo scripts
docs/                 conventions, physics, multirotor, control and viewer notes
index.html            Vite entry point for the viewer
vite.config.ts        base path and build configuration
out/                  generated CSV traces (gitignored)
dist/                 built static viewer (gitignored)
```
